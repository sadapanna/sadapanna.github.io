# sadapanna.github.io

Coming-soon website for Sadapanna, hosted on GitHub Pages.

## Pages

- `index.html` — landing page (coming soon, projects teaser, about, contact)
- `privacy/` — Privacy Policy (served at `/privacy/`)
- `terms/` — Terms & Conditions (served at `/terms/`)
- `arrow-flux/privacy-policy/` — Arrow Flux app Privacy Policy, for Play Store/App Store listing (served at `/arrow-flux/privacy-policy/`)
- `app/inkflow/` — InkFlow web app: font/text → animated write-on Lottie, runs entirely client-side (served at `/app/inkflow/`)
- `mind/` — Sadapanna Mind, the blog. Post list at `/mind/`; each article is a
  pre-built static page at `/mind/<slug>/`.

Plain HTML/CSS. Content is generated by a small script (see below); the site
itself is served statically by GitHub Pages.

## Content: Firestore lists + pre-built article pages

- **Lists** — the home "What's in the works" cards and the `/mind/` post list are
  stored in Cloud Firestore and rendered client-side with cursor-based "Load more"
  pagination. Firestore is **view-only** to the public (see
  [`firestore.rules`](firestore.rules)); all writes go through the seed script.
- **Articles** — each blog post is a pre-built static page at `/mind/<slug>/`, so
  the full content, title, and social tags are in the HTML. This is what makes
  articles index in search engines and preview correctly when links are shared
  (crawlers mostly don't run JavaScript). Generated by `scripts/build-posts.mjs`.
  The old `/mind/post/?slug=…` route redirects to `/mind/<slug>/`.

Key files:

- [`assets/firebase-config.js`](assets/firebase-config.js) — public Firebase web config.
- [`assets/sada-firebase.js`](assets/sada-firebase.js) — Firestore data layer for the
  lists (loads the Firebase SDK from the CDN).
- [`scripts/`](scripts/) — content source (`seed-data.json` + `bodies/`) and the
  seed/build tooling. **To add or edit a project or post, see
  [`scripts/README.md`](scripts/README.md)** — the short version is: edit
  `seed-data.json`, run `npm run publish`, commit & push.

> **CSS cache-busting:** the shared stylesheet is linked as `styles.css?v=N`.
> When you change `styles.css`, bump `N` (search-replace `?v=` across the HTML)
> so browsers/Cloudflare fetch the new file instead of a cached copy.
